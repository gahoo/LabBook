# 跨天预约开发任务 (Overnight Booking Tasks)

## Phase 1: 核心查询机制与重构

- [ ] **重构区间交叉查询 (`server.ts`)**
  - 重构所有获取预约的 SQL 查询，废除使用 `IN (date, -1 day, +1 day)` 等容易翻车的过滤方式。
  - 更改为严谨的时间交叉判定：`start_time < '${nextDayMax}' AND end_time > '${prevDayMin}'`，确保当前视窗内能精确找出横跨覆盖的订单。

## Phase 2: “午夜分段”后端校验逻辑

- [ ] **按天分段的时段覆盖校验 (`server.ts`)**
  - 当仪器的 `allowOutOfHours === false` 且预约跨日时，抛弃当前的粗暴起停时分比较。
  - **实现：** 自动将预约沿 00:00 分割成首日、中间日、尾日的单独片段。
  - 针对每个日期，获取其对应的开放时间 `dayRules`。
  - 再将每一个单日时间片段去跟它该日的开放时间组合做比对，只有所有的日截断分别全部合法，整体才算合法。

## Phase 3: 前端展示“斩断视窗”

- [ ] **预约日历横条显示优化 (`Booking.tsx` 等)**
  - 根据当天的 0:00 - 24:00，使用 `Math.max(res.start, 0:00)` 和 `Math.min(res.end, 23:59:59)` 来剪裁每一个长条方块。
  - 给跨过的边缘（左侧跨或者右侧跨）增添锯齿边或者渐变消失样式，或增加一个右箭头提示 `>>>`，用来直观表达这不仅限于当天。

## Phase 4: “智能+1天”前端录入体验

- [ ] **结束时间选择器的跨日推断 (`Booking.tsx`)**
  - 不引入沉重的双日期选择器。继续使用双 HH:mm 时分输入。
  - 通过 `endHHMM < startHHMM` 判定，如果是这种倒挂情况，强制内部对象往上 `+1 day`（例如 23:00 - 02:00）。
  - UI 显示上加亮 `(+1 天)` 文本提示，以明确知会用户。
- [ ] **时长校验约束提醒 (`Booking.tsx`)**
  - 一旦触发推断后，检查最终时长，依然遵循最大可用时长（例如最大设定是 4小时），若超越提示“超过单次最长预约限制”。

## Phase 5: 测试验证

- [ ] 验证：当 maxDurationMinutes 大于 24 小时时的跨两日情况防滥用测试。
- [ ] 验证：半夜 23点 ~ 02点 预约的冲突检测功能，并在禁止非营运时段的机器上测试它是否被正确拒绝或允许。
