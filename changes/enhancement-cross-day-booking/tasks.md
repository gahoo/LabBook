# 跨天预约开发任务 (Overnight Booking Tasks)

## Phase 1: 核心查询机制与重构

- [x] **重构区间交叉查询 (`server.ts`)**
  - 重构所有获取预约的 SQL 查询，废除使用 `IN (date, -1 day, +1 day)` 等容易翻车的过滤方式。
  - 更改为严谨的时间交叉判定：`start_time < '${nextDayMax}' AND end_time > '${prevDayMin}'`，确保当前视窗内能精确找出横跨覆盖的订单。

## Phase 2: “午夜分段”后端校验逻辑

- [x] **按天分段的时段覆盖校验 (`server.ts`)**
  - 当仪器的 `allowOutOfHours === false` 且预约跨日时，抛弃当前的粗暴起停时分比较。
  - **实现：** 自动将预约沿 00:00 分割成首日、中间日、尾日的单独片段。
  - 针对每个日期，获取其对应的开放时间 `dayRules`。
  - 再将每一个单日时间片段去跟它该日的开放时间组合做比对，只有所有的日截断分别全部合法，整体才算合法。

## Phase 3: 前端展示“斩断视窗”与网格优化

- [x] **预约日历横条显示优化 (`Booking.tsx` 等)**
  - 根据当天的 0:00 - 24:00，使用 `Math.max(res.start, 0:00)` 和 `Math.min(res.end, 23:59:59)` 来剪裁每一个长条方块。
  - 给跨过的边缘（左侧跨或者右侧跨）增添锯齿边或者渐变消失样式，或增加一个右箭头提示 `>>>`，用来直观表达这不仅限于当天。
- [x] **网格时间范围动态计算与布局优化 (`Booking.tsx`)**
  - 使用所有仪器的最值（最早至最晚）来撑大 X 轴，代替写死的 `08:00 - 22:00`，全日运行则自动展示完整的 `00:00 - 24:00`。
  - 左侧列设定 `position: sticky`，在滚动日理时保持可见并带有层次阴影隔离。
  - 在页面进入和初始化重绘时，将网格内容的容器的 `scrollLeft` 平移滑动至 `08:00` 的位置区域，减少用户拖拽操作。

## Phase 4: “日期+时间”统一前端录入体验

- [x] **统一的起止时间选择器 (`Booking.tsx`)**
  - 为预定表单引入独立的“结束日期”选择器。用户的输入项变更为：`开始日期`、`开始时间` 和 `结束日期`、`结束时间`。
  - 添加联动逻辑：在未显示设置结束日期前，结束日期默认跟随开始日期同步发生改变，以降低常规当日预约的点击成本。
- [x] **用户与管理员的修改表单对齐**
  - 在前端修改预约的地方，采用相同的统一日期+时间组件，确保不论在哪里编辑，都具备跨天变更的自由度。
- [x] **精确的时长校验约束提醒 (`Booking.tsx`)**
  - 合并两个日期与时间的输入并计算绝对时间戳（Timestamp）。
  - 严格检查并阻拦：`结束时间 <= 开始时间` 以及 `预约总时长 > min(maxDuration, limits)`。

## Phase 5: 测试验证

- [x] 验证：当 maxDurationMinutes 大于 24 小时时的跨两日情况防滥用测试。
- [x] 验证：半夜 23点 ~ 02点 预约的冲突检测功能，并在禁止非营运时段的机器上测试它是否被正确拒绝或允许。
