# 跨天预约功能设计 (Overnight Booking Design)

## 1. 业务范围界定 (Scope Definition)

### 1-1. 多天预约防滥用 (Max Duration Protection)
系统目前已经具备 `maxDurationMinutes` 的限制机制。例如管理员设置仪器最长预约时间为 4 小时或是 12 小时。只要确保开始时间和结束时间之差（按真实时间戳计算）不超过该限制，即可从根本上防止用户强行占用多天。我们的核心诉求不仅是“防盗刷”，而是合法地支持“跨零点（过夜）实验”。

### 1-2. 支持跨天的必然性 (Why strictly prohibit is bad)
如果一刀切地禁止跨天预约，当科研人员需要进行 `23:00` 到次日 `02:00` 的连夜实验时，他们将被迫：
1. 拆分为 `23:00~23:59` 和 `00:00~02:00` 两个预约。
2. 进行两头上机操作、两头下机操作。
3. 增加因为忘点下机导致的违规风险和多重费用的计算复杂度。
因此，提供良好的“跨天（过夜）预约支持”远胜于一刀切的禁止。

## 2. 后端校验改造方案

### 2-1. 开放时段（营业时间）的午夜分段校验
当前针对 `allowOutOfHours: false` 的校验是一个硬伤。由于只比较了单天的 HH:mm 数字，如果遇到 23:00~01:00 这种时段它就无法正常执行判断。

**核心解决算法 (Midnight Split Check)**：
当遇到用户提交的跨日时间段（例如 Day1 23:00 - Day2 02:00）：
1. 在内存中将这段预约在 **午夜 00:00** 强制切断，变成：
   - 块A：`Day1 23:00` 到 `Day1 23:59:59`
   - 块B：`Day2 00:00` 到 `Day2 02:00`
2. 分别获取 `Day1` 的营业时间数组 和 `Day2` 的营业时间数组。
3. 校验【块A】是否完全被 `Day1` 当初开放时间覆盖。
4. 校验【块B】是否完全被 `Day2` 当初开放时间覆盖。
5. 只有所有块都被完全覆盖了，且不大于 `maxDurationMinutes` 限额，才算合法预约。这就是在兼顾防漏洞和好体验之下的最终解。

### 2-2. Fetch 查询区间的优化
当前很多查询（尤其是前端网格图渲染）依赖 `date(start_time) IN (今天, 昨天, 明天)`。既然现在最大预约时长能够兜底限制防滥用，对于日常查询而言这通常是够用的（因为很少遇到长达几个月的机器占用）。
更加严谨的做法是在拉取当天的数据时改为：`起始时间 < 视窗终点 AND 结束时间 > 视窗起点`，这种交叉判定可以彻底规避跨日记录丢失的问题。

## 3. 前端展示与交互解决方案

### 3-1. 网格双截斩断显示 (Viewport Clipping)
前端网格是每天 0 点到 24 点。如果某个预约从昨天晚上横跨到今天早晨：
- **第一天网格：** 绘制起点为真实起点，终点截断为 `23:59:59`。
- **第二天网格：** 绘制起点截断为 `00:00:00`，终点为真实终点。

### 3-2. 交互方式调整：统一的“日期+时间”完整选择器
在前端拖拽与填报预定表单，以及修改预约时间时，摒弃容易产生歧义的“结束时间倒挂自动+1天”玄学逻辑。
- **统一 UI 范式**：无论是普通用户新建预约，还是修改已有预约，开始时间和结束时间均提供完整的【日期选择 + 时分选择】。
- **减少输入摩擦**：当用户在侧边栏修改了“开始日期”或点击网格时，自动将“结束日期”默认同步为该日期。如果用户确实需要跨日，只需手动调整“结束日期”为次日即可。
- **精确防错**：结合完整的时间戳，在前端更精确地提前拦截 `End <= Start` 或 `Duration > MaxDuration` 的操作。这也保证了普通用户端与管理员端表单的高度复用和体验统一。

### 3-3. 网格可用时间刻度与视图优化 (Grid Viewport & Boundaries)
当前的网格时间范围固定在了 08:00 - 22:00，这会截断或者直接无法展现跨越到深夜和早晨的预约块。
- **动态列边界 (Dynamic Grid Boundaries)**：在前端加载所有仪器的开放规则后，求出全局“最早开放时分”和“最晚开放时分”。以此作为日历网格动态渲染的时间基准。如果全天均允许预约，则退至展示 00:00 - 24:00。
- **默认视口 (Default Viewport Start)**：为了避免每次打开时满眼的黑夜刻度导致找不着北，可以通过设定内部容器（或 CSS 滚动锚点）让网格容器在初始化时，默认向右平移滚动落在 08:00 处，优先展示主流的日间营业范围（8:00~18:00）。
- **锁左侧栏 (Sticky Headers/Columns)**：最左侧呈现日期信息的列（比如“今天”、“明天”）必须设置 `position: sticky; left: 0; z-index: 10;`，甚至在它的背后叠加一些背景和阴影以区分滑动区。哪怕横向划开到 23 点，用户也无需丢失 Y 轴的指向。
