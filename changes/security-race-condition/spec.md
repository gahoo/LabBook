# 规格说明书：预约并发竞态条件加固 (Race Conditions)

## 1. 背景与业务需求
安全审计报告指出，系统中新增预约（`/api/reservations`）与修改预约（`/api/reservations/update`）接口中，对于“冲突时段查询”和“数据插入”是割裂为两次独立的操作。在面对未来可能演进出的异步机制或多进程环境时，极易形成多个并发请求查到“同一无冲突结果”进而并发出双重预订的严重漏洞。
尽管当前借助 Node.js 单线程配合 `better-sqlite3` 同步阻塞驱动，避免了事件循环的上下文切换从而形成“侥幸安全”，但仍需要补齐标准架构下赖以保证原子性的数据库事务防线。

## 2. 方案设计
使用 `better-sqlite3` 原生的同步型事务函数 `db.transaction()` 将“预判冲突”和“写操作”连结成一个原子任务。
*   **影响范围**：
    *   `POST /api/reservations`：包含冲突判定检查与新建记录的连贯行为。
    *   `POST /api/reservations/update`：包含校验旧数据一致性与时间重叠判定及库表更新的连贯行为。
*   **具体实现细则**：
    *   在相关路由体中抽取出一个局部的 `const tx = db.transaction((params) => { ... })` 匿名或包装函数。
    *   将查询时段是否重叠以及 INSERT / UPDATE 的逻辑移入包装函数。如果判定逻辑发觉冲突或越界，直接通过 `throw new Error('...具体原因...')` 回滚。
    *   原主路由中的过程使用 `try { tx() } catch(e) { }` 包裹兜底，截获逻辑抛出的特定错误，还原为 400 状态码返回客户端即可保证业务不受影响且逻辑严密。
    *   `better-sqlite3` 开启事务通常为 `BEGIN IMMEDIATE` 模式（阻塞写并发的同时保留读响应），极轻量、不会对小型实验室场景增加负担。
