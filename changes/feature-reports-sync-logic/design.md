# 报表统计图表联动逻辑梳理 (feature-reports-sync-logic)

## 需求理解理解 (User Requirement Clarification)

您完全说到了点子上！您所期望的就是**最合理且清晰的设计思路**：“时长费用统计表”和“统计图表”作为报表页面的两个独立展示模块，应该分别拥有独立的“是否与详细预约记录表联动”控制权。

我之前提到的“局部筛选结果”，指的就是“时长/费用统计表”表头的那排搜索框（比如单独搜索某个用户或设定最低时长）。原先的代码架构由于没有将这两个模块梳理开，导致图表在读取数据时，不小心读取了“经过那些搜索框过滤后”的数据，所以图表会莫名其妙地发生变化。

完全按照您的想法，我们需要将它们“解耦”，设计如下：

## 核心设计 (Core Design)

### 1. 独立的状态控制 (Independent States)
移除原先共用的 `syncWithFilters` 状态，替换为两个独立的开关状态：
- `syncChartWithFilters`：控制【统计图表】是否与详细记录表联动。
- `syncStatsWithFilters`：控制【时长/费用统计表】是否与详细记录表联动。

### 2. 独立的数据聚合引擎 (Decoupled Data Aggregation)
为两个模块分别建立数据聚合逻辑：
- **统计图表的数据源 (`chartBaseData`)：**
  - **启用联动时：** 读取并聚合“详细预约记录表”经过筛选后的结果 (`filteredReportReservations`)。
  - **未启用联动时：** 直接读取该时间区间内的所有完整数据（不进行额外过滤）。
  - **注：** 图表将直接使用该数据源进行绘制，**不受**下方时长费用统计表内的那些搜索框影响。

- **时长/费用统计表的数据源 (`statsBaseData`)：**
  - **启用联动时：** 读取并聚合“详细预约记录表”经过筛选后的结果 (`filteredReportReservations`)。
  - **未启用联动时：** 读取时间区间内的所有完整数据。
  - **内部再过滤：** 时长/费用统计表将在这份数据的基础上，再应用它自己专属的表头筛选器（如特定的用户、时长区间等），最终渲染出表格。

### 3. 用户界面补充 (UI Updates)
- 在【时长/费用统计表】的表头右侧，补充一个类似于现在图表区域的“与上方筛选联动”按钮，用于控制专属该表格的联动逻辑。
- 确保所有的文案明确易懂（比如统称为“与详细记录筛选联动”），图表和表格的独立操作一目了然。

采用这种方式，两个模块都拥有完美的内聚性，同时也能满足不同场景的灵活分析需求。
