# 01 — 实现统一预约看板骨架及报表数据解耦呈现

**要构建什么:** 将原有的“预约管理”与“报表”页面合并为一个统一的后台预约看板（UnifiedReservationsTab）。用户访问该看板时，能够查看到轻量级的预约记录列表（包含报表状态与审批状态的双层复合展示），同时可以切换至图表和统计子标签页。旧版严重拖慢性能的 `/api/admin/reports` 接口将被废弃，后端将分离出专用于重度数据聚合的 `/api/admin/reservations/stats` 接口和轻量级的增强列表接口。

**前置阻碍 (Blocked by):** 无 — 可立即开始

- [ ] 后端：新增 `GET /api/admin/reservations/stats`，专门执行原有的多维度分组计算。
- [ ] 前端：从首页导航移除 `ReportsTab`。
- [ ] 前端：创建 `UnifiedReservationsTab` 包含列表与统计子视图。

# 02 — 实现编辑抽屉中的基础预约信息与上机信息物理隔离

**要构建什么:** 在统一的预约看板中点击编辑预约时，管理员会看到一个被重新拆分为多个标签页的抽屉（ReservationEditDrawer）。修改预约基础信息（如联系方式、导师）和修改上机日志（实际起始时间）被完全物理隔离到两个独立的 Tab 中。保存基础信息不会触发任何违规或惩罚逻辑，只有明确修改实际上机时间时，才会通过独立的接口交互重新计算迟到/超时和计费。

**前置阻碍 (Blocked by):** 01 — 实现统一预约看板骨架及报表数据解耦呈现

**状态:** ready-for-agent

- [ ] 前端：重构 `ReservationEditDrawer`，划分为“预约信息”、“上机信息”和“违规记录”三个 Tab。
- [ ] 前端：为“预约信息”和“上机信息”各提供独立的保存逻辑，仅传递必要的修改字段。
- [ ] 后端：改造 `PUT /api/admin/reservations/:id`，确保当且仅当传入实际上机/下机时间发生变动时，才去触发系统违规（迟到/超时）检测。

# 03 — 规范化违规 API 并实现在预约抽屉中的独立管理

**要构建什么:** 系统中涉及的所有人工违规与系统违规相关操作都被统一在规范的 RESTful `/api/admin/violations` 命名空间下。管理员在预约抽屉的“违规记录”标签页中，除了能只读查看系统违规，还能完全独立地新建、编辑（修改类型/备注）或撤销人工违规，无需像以前那样通过全量数组提交和覆盖。
