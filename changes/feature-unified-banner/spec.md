# 全局统一审批与待办看板 (Unified Approval Banner)

## 背景 (Background)
管理后台目前存在多类需要管理员人工审核的业务：
1. **待审批预约 (Pending Reservations)**：非开放时段预约、忙时超长预约、未启用自动审批仪器的预约。目前管理员只能在“预约记录”巨大表格中筛选并弹窗修改，链路繁琐且极易遗漏强时效性的预约。
2. **白名单准入申请 (Whitelist Applications)**：目前在 `ReservationsTab.tsx` 顶部硬编码了一个内联横幅，但与预约管理业务不够契合。
3. **违规申诉处理 (Violation Appeals)**：用户被扣分或封禁后提交的申诉，目前淹没在违规记录列表中，缺乏主动提醒。

三者本质上是管理员进入系统后最关心的**三大核心日常待办（Inbox）**。若每个页面各写一个独立 Banner，不仅代码大量重复，还会导致页面堆叠拥挤。因此，需将 Banner 抽象为全局通用的待办看板组件。

## 目标 (Goals)
1. **统一收敛**：抽离通用的 `UnifiedApprovalBanner` 组件，在 `src/pages/Admin/index.tsx` 顶层统一承载三大待办。
2. **Tab 智能感知优先**：
   - 切换到 `reservations`（预约管理）时，优先高亮展示“待审预约”；
   - 切换到 `equipment`（仪器管理）时，优先高亮展示“白名单申请”；
   - 切换到 `violations`（违规惩罚）时，优先高亮展示“违规申诉”；
   - 若当前 Tab 对应的类型无待办，自动平滑显示其他有待办的项目；
   - 支持管理员手动点击切换不同分类。
3. **无待办即静默**：若三大类型待办总数为 0，Banner 完全隐藏，0 像素占用。
4. **统一极速交互**：统一胶囊药丸（Capsule/Pill）排布、Hover 浮层详情、一键通过、一键驳回，并支持全局撤销（Undo Stack）。

## 详细设计 (Detailed Specifications)

### 1. 挂载位置
- 位于 `src/pages/Admin/index.tsx` 的 Header（管理后台标题及 Tab 导航栏）下方、具体子 Tab 内容展示区上方。

### 2. 交互与布局
- **外框**：琥珀色警示卡片（`bg-amber-50 border border-amber-200 rounded-xl px-4 py-3 mb-6`）。
- **左侧切换栏**：
  - `待审预约 ({count})` (带 Clock 图标)
  - `白名单申请 ({count})` (带 ShieldCheck 图标)
  - `违规申诉 ({count})` (带 Scale / AlertTriangle 图标)
  - 支持点击切换当前展示的胶囊流。
- **右侧胶囊流**：
  - **待审预约胶囊**：
    - 主显文本：`申请人 · 仪器名 · 预约时段`
    - 标记 Tag：`时段外`、`超长`、`人工审`
    - Tooltip 浮层：展示学号、导师、精确时间、预估费用、耗材数、预约备注
    - 动作：通过（更新为 approved 并发通知）、驳回（标记为 rejected 并发通知）
  - **白名单胶囊**：
    - 主显文本：`申请人姓名`
    - Tooltip 浮层：仪器名称、学号、导师、申请理由
    - 动作：通过、驳回（复用现有白名单审批 API）
  - **违规申诉胶囊**：
    - 主显文本：`申诉人 · 违规类型 · 扣分/惩罚`
    - Tooltip 浮层：申诉理由、违规发生时间、设备名称、原违规原因
    - 动作：通过（撤销违规）、驳回（可快速填写或选择理由）
- **右上角统一撤销 (Undo)**：
  - 维护统一的撤销动作栈，误点后可秒级撤销恢复为待办。

### 3. API 支撑与对齐
1. **预约待审**：
   - 列表：`GET /api/admin/reservations?status=pending`
   - 快速审批：`PUT /api/admin/reservations/:id`（status: approved / rejected）或专用审批端点
2. **白名单待审**：
   - 列表：`GET /api/admin/whitelist/applications?status=pending`
   - 审批与撤销：现有的 `/approve`、`/reject`、`/undo` 保持不变
3. **申诉待审**：
   - 列表：`GET /api/admin/violations?appealStatus=appealing&startDate=2000-01-01&endDate=2099-12-31`（或专属快捷查询端点）
   - 审批：现有的 `POST /api/admin/violations/:id/revoke`（通过并撤销违规）与 `POST /api/admin/violations/:id/reject-appeal`（驳回申诉）

### 4. 冗余清理
- 移除 `ReservationsTab.tsx` 顶部原本内联的白名单 Banner，避免重复渲染与数据请求。

### 5. 视图密度切换（极简模式）与 Cookie 持久化
- **功能目标**：为满足不同管理员的日常审查习惯与工作负载，支持在“详细视图”与“极简视图”之间无缝切换。
- **开关入口位置**：
  - 固定放置在**胶囊流（Capsule Stream）的最左侧**（索引为 0 处），紧邻胶囊列表；
  - 切换按钮右侧配有一根轻量垂直分割线（`w-[1px] h-5 bg-amber-300/60`），在视觉上将“视图控制器”与“待审批胶囊列表”清晰隔开；
  - 固定在最左侧可确保在审批减少、胶囊增减或换行时，控制按钮本身位置绝对稳定、不产生排版跳动。
- **图标与双态交互**：
  - 详细模式下：展示 `List` 图标，Tooltip 提示“切换为极简视图”；
  - 极简模式下：展示 `LayoutList` 图标，Tooltip 提示“切换为详细视图”。
- **展示内容对比**：
  - **详细模式（默认）**：
    - 待审预约：`申请人 · 仪器名 · 预约时段 | ✓ ✕`
    - 白名单：`申请人 · 仪器名 · 申请理由 | ✓ ✕`
    - 违规申诉：`申诉人 · 违规类型 · 申诉理由 | ✓ ✕`
  - **极简模式（高密度）**：
    - 各类别胶囊均收敛为：`申请人姓名 | ✓ ✕`
    - 宽度缩减约 60%，成倍提升单位空间内的待办容纳量。
- **完整浮层（Tooltip/Popover）保留**：
  - 在极简模式下，鼠标悬停（桌面端）或点击姓名区域（移动端）依然完整弹出详细卡片，展示设备名、具体起止时段、申请理由、备注等全量数据，确保快速决断与深入核查两全其美。
- **Cookie 持久化**：
  - 写入与读取客户端 Cookie：`admin_banner_compact=true/false`；
  - 设置 `path=/; max-age=31536000; SameSite=Lax`（有效期 1 年）；
  - 组件初始化时从 Cookie 读取初始状态，用户切换时即时同步更新 Cookie，保证刷新与重登后习惯不丢失。

### 6. 移动端（Mobile）自适应精简与触控优化
- **顶栏空间释放**：
  - 在小屏幕移动端（`< 768px`），自动隐藏左侧的警示图标和“待办事项”四个字（`hidden md:flex`），节约约 100px 横向空间；
  - **Tab 标签自适应收缩**：
    - 当前激活的 Tab：保留展示 `[图标 + 分类文本 + 数量角标]`（例如 `[时钟] 待审预约 2`）；
    - 非激活的 Tab：自动隐藏分类文本（`hidden md:inline`），仅保留 `[图标 + 数量角标]`（例如 `[白名单图标] 1`、`[天平图标] 3`）；
    - 右侧保留 `[撤销]` 按钮。顶栏可在手机单行内舒展排布，彻底杜绝横向滚动或拥挤折行。
- **触控体验与尺寸微调**：
  - 移动端胶囊整体适当放大（内边距增大至 `px-3.5 py-1.5`，姓名文字放大至 `text-sm`）；
  - 通过（✓）和驳回（✕）按钮在移动端保证足够的操作间距与热区（不低于 `32px × 32px`），消除触屏误操作隐患；
  - 移动端点击胶囊的姓名区域可展开/折叠查看浮层详情，点击操作按钮直接审批。

## 7. Tab 顺序与初次载入动态隐藏规范 (Tab Order & Initial-Load Auto-Hide)

### 7.1 Tab 顺序与主导航镜像对齐
待办条的 Tab 标签顺序、胶囊流渲染顺序及无待办降级优先级与后台顶部主 Tab 保持严格一致：
$$\text{白名单 (对应仪器管理)} \rightarrow \text{待审预约 (对应预约管理)} \rightarrow \text{违规申诉 (对应违规惩罚)}$$
- 切换主 Tab 时，优先高亮当前主模块对应的待办类别。
- 当当前类别待办为 0 时，降级兜底顺序亦为：`whitelist` $\rightarrow$ `reservations` $\rightarrow$ `appeals`。

### 7.2 初次载入动态隐藏（Initial-Load Auto-Hide）与平滑会话
- **初次进入页面判定**：
  - 页面初次载入拉取数据时，若某类别待办数量为 0，则该类别的 Tab 初始隐藏，不占据顶栏空间；
  - 待办数量 $> 0$ 的类别正常展示对应 Tab。
- **会话期间平滑展示（不跳跃）**：
  - 初始展示出的 Tab 在管理员操作过程中，即便其待办项全部被审批完成（数量降至 0），在当前页面会话（Session）中**依然保留该 Tab**，展示“暂无...”空状态；
  - 避免“一点击通过，Tab 瞬间消失、胶囊流硬切”的突兀跳跃；
  - 只有在管理员整页刷新（重新进入页面）且该类目依然为 0 时，才会被彻底自动隐去。
- **动态增量显现**：
  - 若初始为 0 的类别在后台轮询或重新拉取中产生了新待办（`count > 0`），该 Tab 自动显示。

### 7.3 跨主 Tab 撤销栈保留（后悔药）
- 撤销栈（`actionStack`）在组件内跨主 Tab 切换时完整保留；
- 管理员无论在哪个主页面，顶栏的“撤销”按钮均保持可用；
- 点击撤销能够无缝撤回上一笔审批操作，并触发全局更新事件。
